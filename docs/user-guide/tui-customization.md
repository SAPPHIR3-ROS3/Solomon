# Live TUI customization

Solomon's TUI 2.0 personalization is designed to remain available beyond the prototype phase. Its permanent runtime is the local `tui/` module. It is already connected to the Bubble Tea laboratory; the current readline frontend has not been migrated and is not silently replaced.

## Start the visual laboratory

From the repository root, run `make tui-dev` to open the Mission TUI with hot reload. F7 or `/components` opens the component map. Alternatively, from `tui prototipe`, run `make dev` to start directly in the component map. Both commands use the same development supervisor. Keep that terminal open while editing. The component map uses the same renderers as full conversations. Use Up/Down to choose a component, Tab to change its state, F1–F4 to compare layouts, and Escape to return to the conversation. F7 or `/components` reopens the map. These are default shortcuts and can be remapped.

For configuration-only editing without Go rebuilding, run `make components` once or launch an existing `laboratory --components` binary. Normal launches watch configuration but do not watch or compile Go source.

## Change appearance and shortcuts without compiling

The interface file is `~/.solomon/customization/tui/interface.json`, respecting `SOLOMON_HOME`; `SOLOMON_TUI_CONFIG` or the frontend's `--config <path>` selects another file explicitly. `make config` creates the default file without overwriting an existing file. The running frontend checks changes every 250 ms.

You can change colors, home width, margins, composer rows, suggestion count, border style, interface text and key bindings. Partial JSON objects keep unspecified defaults. A typical partial configuration changes `layout.home_width`, `colors.gold`, `keys.global.new_thread` and `keys.composer.newline`. The full supported schema is generated by `go run ./cmd/tui-config --print` from the `tui` module.

Keymaps have `global`, `composer`, `suggestions`, `picker` and `components` contexts. Bindings reference actions such as `send`, `newline`, `new_thread`, `toggle_details`, `models` or `components`, not Go functions. Hint labels update with the active bindings. Ctrl+C remains an emergency exit. Conflicts, unknown actions, malformed colors and invalid JSON are rejected together; the last valid configuration remains active and an error appears in the interface. Saving a valid document recovers immediately.

Changing an existing binding requires no compile or restart. New actions and different Go behavior require a build. Shift+Enter still depends on the terminal sending a distinct extended key sequence; Ctrl+J/Alt+Enter remain supported fallbacks unless remapped.

## Go-code development

In `make dev`, a source change compiles a single candidate in the background. A build error keeps the old interface usable and displays a bounded diagnostic. After a successful build, the interface checkpoints its state, restores the terminal and yields ownership to the replacement process. Draft, reading position, selected layout/mode, menus, expanded cards and component selection are restored.

No daemon restart occurs. In the laboratory, static transcript content and simulated streaming are restored too. When integrated into the production Bubble Tea frontend, the UI must reconnect to daemon-owned chats and jobs rather than serializing the harness. A failed handoff or incompatible candidate does not intentionally clear the previous session.

## Checks and scope

Use `make test-live` for the focused no-restart configuration test and `make test-dev` for the Linux end-to-end compile/handoff test. The permanent module has its own `make test`/`make vet` targets; root `make test` includes its tests. The laboratory's `make test` retains full rendering, input and scrolling regressions. Neither development mode nor the component map runs the full test suite on every visual save.

This feature does not install third-party watcher packages or execute configuration files. It does not alter provider settings, credentials, branch selection or the old TUI. Runtime configuration changes are permanent capabilities of the new frontend; automatic Go rebuilding remains development-only.

## Mouse interaction

Mouse clicks are enabled by default. In the Bubble Tea frontend, left click activates model/reasoning selectors, Agent/Chat, send/stop, slash suggestions, layout controls, component selection and artifact header folding. Press and release do not execute an action twice. Areas are measured from the final rendered screen, including margins, Unicode widths, scrolling and resize. Decorative workspace/branch fixture labels are not presented as live repository actions.

Set `mouse` to `false` in the live interface JSON to disable terminal mouse reporting without rebuilding. This restores native terminal mouse handling; a Shift-drag selection may also be available depending on the terminal. Clicking inside composer text does not yet reposition an editing cursor. The normalizer handles SGR and legacy X10 click reports, including fragmented input, without inserting mouse bytes into the draft. The reusable `tui/interaction` module provides hit regions independently of Bubble Tea.
