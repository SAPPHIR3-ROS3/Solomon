Installation and quickstart

Get started with the Solomon AI agent

Install Solomon, choose a model and open a project. Use the open-source, local-first AI agent for research, file tasks, automation and coding from your terminal, a native desktop window, a browser or a CI pipeline.

Solomon is early release software under the MIT license. APIs, behavior and data formats may change.

Install First session Models Desktop, web and CI Next steps

Install on Linux, macOS or Windows

macOS and Linux

curl -fsSL https://raw.githubusercontent.com/SAPPHIR3-ROS3/Solomon/main/scripts/install.sh | bash

Windows PowerShell

irm https://raw.githubusercontent.com/SAPPHIR3-ROS3/Solomon/main/scripts/install.ps1 | iex

The installers set up required dependencies and the desktop application. On macOS, the installer uses Homebrew and may ask for administrator credentials. See the full installation guide for dependency and PATH details.

Install the CLI with Go

If you already have Go 1.25 or newer, use:

go install github.com/SAPPHIR3-ROS3/Solomon/v2026/cmd/solomon@latest

Make sure Go's binary directory is on your PATH. This method installs the CLI; the first normal launch downloads and registers the matching desktop application. It does not provision the optional internal web-search backend.

Verify the installation

Reload your terminal, then check that Solomon is available:

solomon version

Start your first AI agent session

Open the project you want to work on and launch Solomon:

cd /path/to/your/project
solomon .

The first run guides you through provider, credentials and model setup. Then describe a task. For example, ask it to work with local documents:

Read the documents in this folder and create a summary of the decisions and open questions.

For research, try /chat and ask a question that needs web sources. For coding, ask the agent to explain a codebase or implement a change and run its tests. Solomon can read and edit files and run shell commands. Configuration, sessions, plans, skills and logs are stored under ~/.solomon, partitioned by workspace.

Connect a cloud provider or a local model

Solomon supports OpenAI-compatible APIs, the native Anthropic Messages API and integrations with existing ChatGPT, Claude and Cursor accounts. Add a provider with /connect and switch the active model with /models.

For local models, connect a runtime that exposes an OpenAI-compatible endpoint. Once the runtime, model and Solomon are installed, local file, coding and shell tasks can work offline. Cloud models, web search and downloads need a network connection.

Local-first refers to where Solomon stores its state. When you select a cloud provider, prompts and relevant project context are sent to that provider. The configuration guide covers provider settings and credentials.

Use the desktop app, web interface or CI runner

Native desktop application

solomon desktop

Open the native GUI with chat, editor and terminal panels over the same engine and local sessions.

Local web interface

solomon server

Start the local server and open its GUI in a browser. See the usage guide for network access and server options.

Headless automation and CI

solomon exec --jsonl --fail-on-tool-error "run the project tests and fix failures"

Automate a file task, run a coding check or execute another agent prompt without the interactive REPL, with JSONL events and stable exit codes. Use the GitHub Actions example to integrate Solomon into a pipeline.
