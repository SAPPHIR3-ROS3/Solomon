Research and answers

Principles

Built to stay out of your way,
and out of your repo.

01

Local-first

Config, chats, plans, skills and logs live under ~/.solomon, partitioned per workspace. Nothing is written into your repository, and there is no hosted service in the middle.

02

Your models, not ours

Any endpoint that speaks OpenAI Chat Completions or native Anthropic, a local runtime on your laptop, or an account you already pay for. No gatekeeping, no markup, no middleman.

03

One binary

A single Go executable for Linux, macOS and Windows. The REPL, the headless runner, the local server, the desktop app and self-update all ship inside it.

Code mode

Go code mode.
Fewer tool round trips.

In agent mode the model does not call tools one at a time. It discovers what it needs with searchTools, then writes a short Go program that orchestrate runs in a WASM sandbox, chaining reads, searches, edits and shell commands in a single step.

  • Batches many operations into one model turn
  • Keeps large intermediate results out of the context window
  • Every call carries a human-readable intent

Features

Research, automation and coding.
One extensible AI agent.

checkpoints

Undo the agent.

Every turn gets an id like [#012]. /goto rewinds or forks the transcript and puts every edited file back the way it was. Bad turns cost seconds, not afternoons.

repl

Ask while it streams.

/btw opens a side question without interrupting the turn in flight. Reasoning is shown as it happens, and /terminal on turns the prompt into a shell with the agent one keystroke away.

research

Research with receipts.

Deep research jobs fan out across DuckDuckGo, SearxNG, Brave, Bing, Google PSE, Exa and Parallel, check the evidence, and hand back an HTML report you can actually cite.

subagents

Delegate, then move on.

Nested agents with their own system prompt, their own model and their own budget. Run them inline or in the background and collect the result when you want it.

plans

Plans that outlive the chat.

A plan is a file with a design and checkable todos, not a message that scrolls away. buildPlan promotes it straight into implementation, one verified item at a time.

extend

Teach it your house rules.

AGENTS.md and numbered rules shape every turn. Skills install from skills.sh with solomon add; MCP servers from mcp.json join the same tool catalog as the native ones.

Only in Solomon

Nothing here
is accidental.

  1. Nothing silently dropped

    Oversized tool output is truncated for the model but saved in full to a local path it can read in the next turn.

  2. Fail-closed streaming

    Inconsistent SSE chunks are rejected at the harness, so the transcript on disk always matches what really happened.

  3. Intent on every call

    Each tool call carries a short, human-readable reason. A session log reads like a changelog, not a packet capture.

  4. Readable skill history

    /skill:name stays visible in the transcript while the model receives the fully expanded skill.

  5. Per-workspace partitions

    Sessions, plans and logs are keyed by project under ~/.solomon. Two repos never see each other's history.

  6. Safe by construction

    Skill installs accept only skills add and run as direct argv, never through sh -c.

Authorship

Designed by a person.
Not generated.

Solomon is not a repository where a model decided everything and a human pressed enter. Every architectural choice below was taken on purpose by its author, with a reason that can be defended. Models write lines here. They do not get to choose the shape.

Nothing to install besides itself. No runtime, no package manager, no daemon you forgot about.

Questions and answers

About the Solomon AI agent

What is Solomon?
Solomon is an open-source AI agent built in Go for Linux, macOS and Windows. It works with files, runs shell commands, searches the web, produces research reports and builds plans through a terminal, desktop app, local web interface or CI pipeline.
Can Solomon use local models offline?
Yes. Connect Solomon to a local runtime that exposes an OpenAI-compatible API. File, coding and shell tasks with an already installed local model can work offline; cloud providers, web search and downloads require network access.
Which model providers does Solomon support?
Solomon supports OpenAI-compatible endpoints, the native Anthropic Messages API and integrations for existing ChatGPT, Claude and Cursor accounts. Use /connect to add a provider and /models to switch models. See the provider configuration guide.
Where are sessions and configuration stored?
Configuration, sessions, plans, skills and logs live under ~/.solomon, partitioned by workspace. When you choose a cloud model, your prompts and relevant context are sent to that provider.
Is Solomon free and open source?
Solomon is available under the MIT license. Your chosen model provider may charge for API usage or require a subscription. Local models run on your own hardware.
How do I install Solomon?
Use the installer for macOS, Linux or Windows, or install the CLI with Go. Follow the Solomon installation and quickstart guide to start your first session.
