Principles

          
Built to stay out of your way,
and out of your repo.

        

        

          

            01
            
Local-first

            
Config, chats, plans, skills and logs live under ~/.solomon, partitioned per workspace. Nothing is written into your repository, and there is no hosted service in the middle.

          

          

            02
            
Bring your own model

            
Any HTTPS endpoint that speaks OpenAI Chat Completions, native Anthropic, or browser sign-in to the subscriptions you already pay for. Switch with /models mid-session.

          

          

            03
            
One binary

            
A single Go executable for Linux, macOS and Windows. Interactive REPL, headless runs, a local server for the GUI, and built-in updates all ship together.

          

        

      

    


    

      

        

          
Code mode

          
Fewer round trips.
More work per turn.

          
In agent mode the model does not call tools one at a time. It discovers what it needs with searchTools, then writes a short Go program that orchestrate runs in a WASM sandbox, chaining reads, searches, edits and shell commands in a single step.

          
    
            
  • Batches many operations into one model turn
    • 
            
  • Keeps large intermediate results out of the context window
    • 
            
  • MCP tools join the same catalog as native ones
    • 
          

        

        

          
orchestratemain.go


package main

import (
	"fmt"
	"sdk"
)

func main() {
	src, _ := sdk.ReadFile("login.go", "read handler")
	hits, _ := sdk.Grep("RateLimit", "find limiter")
	res, _ := sdk.ShellResult("go test ./...", "run tests")

	fmt.Println(len(src), hits, res.Output)
}

Only in Solomon

          
Small decisions
that add up.

        

        
    
          
  1. 
            
    Checkpoint rewind
    
            
    Every turn gets an id like [#012]. /goto rewinds or forks the transcript and restores edited files, instead of making you start over.
    
          
    2. 
          
  2. 
            
    Plans as artifacts
    
            
    Plans are files with checkable todos that outlive the chat. buildPlan promotes one straight into implementation.
    
          
    3. 
          
  3. 
            
    Nothing silently dropped
    
            
    Oversized tool output is truncated for the model but saved in full to a local path it can read in the next turn.
    
          
    4. 
          
  4. 
            
    Fail-closed streaming
    
            
    Inconsistent SSE chunks are rejected at the harness, so the transcript on disk always matches what really happened.
    
          
    5. 
          
  5. 
            
    Readable skill history
    
            
    /skill:name stays visible in the transcript while the model receives the fully expanded skill.
    
          
    6. 
          
  6. 
            
    Safe by construction
    
            
    Skill installs accept only skills add and run as direct argv, never through sh -c.
    
          
    7. 
        

      

    


    

      

        

          
Headless

          
From your terminal
to your pipeline.

          
solomon exec runs a single prompt without the REPL. Add --jsonl to stream events or --json for one final report. Stdout stays machine-readable and exit codes stay stable.

# one-shot, saved to the project history

solomon exec --jsonl --fail-on-tool-error \
  "run go test ./... and fix failures"
